# Консоль `webdb shell`

Подкоманда `webdb shell` — консоль в духе sqlite3: подключаетесь к работающему
серверу и пишете команды руками, без curl и без HTTP-запросов в коде. Работает
поверх того же REST API, что и клиенты, — то есть ровно с теми же правами,
лимитами и ошибками.

```sh
./bin/webdb shell                                # 127.0.0.1:8080, токен из ./data/token
./bin/webdb shell -addr 127.0.0.1:8099 -data ./data
./bin/webdb shell -token "$(cat data/token)" -addr 127.0.0.1:8099
echo 'SELECT 1 AS one;' | ./bin/webdb shell      # разовый запуск
```

Отдельной сборки нет: консоль живёт в том же бинаре, что и сервер, и делит с
ним HTTP-клиент, так что стоит меньше мегабайта и всегда попадает в релиз
вместе с сервером.

Токен ищется в таком порядке: флаг `-token`, переменная `WEBDB_TOKEN`, файл
`<data>/token`. С JWT всё то же самое — подойдёт любой валидный Bearer, в том
числе выпущенный `webdb token`.

## Команды

### Данные

| Команда | Что делает |
|---|---|
| `.tables` | коллекции и число документов в каждой |
| `.schema [coll]` | «CREATE TABLE», индексы и реальные поля одного документа |
| `.ls [coll] [N]` | документы (по умолчанию 20); фильтры — через SQL, см. ниже |
| `.get COLL ID` | один документ pretty-принтом |
| `.put COLL ID '{json}'` | создать/заменить документ (upsert) |
| `.rm COLL ID` | удалить документ |
| `.index list COLL` | индексы коллекции |
| `.index add COLL FIELD` | создать индекс по полю |
| `.index del COLL FIELD` | удалить индекс |

### Вывод

| Команда | Что делает |
|---|---|
| `.headers on` / `off` | печатать заголовки колонок с подчёркиванием |
| `.mode column` / `list` / `json` | выравнивание по колонкам, через `\|`, либо JSON |
| `.token` | какой токен сейчас используется (маскируется) |

### Сервер

| Команда | Что делает |
|---|---|
| `stats` или `.stats` | счётчики, размеры базы, состояние буфера, RSS |
| `.flush` | дренировать буфер и записать зашифрованный снапшот |
| `.export` | полный экспорт в JSON |
| `.help`, `.quit` / `.exit` | справка, выход |

### SQL

Любой `SELECT` / `WITH` / `EXPLAIN` уходит в `/v1/query` и печатается таблицей:

```
tinydb> SELECT collection, count(*) AS n FROM docs GROUP BY collection;
```

Пишущие запросы (`INSERT`, `UPDATE`, `DELETE`, `DROP`, `PRAGMA`, `ATTACH`)
консоль не отправит — `/v1/query` всё равно read-only. Для изменений есть
`.put`, `.rm` и `.index`.

## Мелочи, которые экономят время

- **Многострочный ввод.** Незакрытая кавычка или скобка переключает приглашение
  на `...>`, так что длинный JSON можно вводить в несколько строк.
- **Комментарии.** `--` до конца строки вырезается (внутри строк — нет).
- **Ошибка не убивает сессию.** Любая команда возвращает промпт обратно;
  внутренние сбои перехватываются и печатаются как `внутренняя ошибка`.
- **Точечный запуск.** `webdb shell -cmd ".tables"` — для скриптов и
  one-liner'ов.
- **Секреты не светятся.** Токен в приглашении не показывается, а `.token`
  печатает только первые и последние 4 символа.

## Ограничения (и почему)

Консоль говорит только по HTTP: у неё нет прямого доступа к файлу базы. Это
означает, что работа с зашифрованным каталогом, правами файлов и квотой
происходит ровно так же, как у сетевого клиента, — что, скорее всего, и нужно
для отладки.

HTTP-клиент здесь свой, минимальный (`internal/httpx/client.go`), а не
`net/http`: разница в бинаре — 3.5 МБ против 6.7 МБ. Сервер от этого тоже
выигрывает — код клиента нужен ему самому, а не отдельной программе. Если
консоль начнёт тянуть `net/http`, стоит задуматься, не вернулась ли мода на
лишние зависимости.
